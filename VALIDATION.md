# Windows x64 milestone validation — 2026-10-22

Scope: Windows x64 Release, MSVC 19.44.35229 / toolset 14.44.35207, SDK 10.0.26100.0, Qt 5.15.2 MSVC2019 x64 official binaries, Qwt 6.3.0 pinned source, CMake 3.31.6 and Ninja 1.11.1.4.

## Results

- Clean scripted builds of Qwt, the GUI, CLI and test harness completed in two independent build directories.
- 17 QtTest cases passed (19 recorded passes including setup/cleanup), using the native Windows Qt platform. Cases cover independent numerical expectations, odd-width grayscale, mixed formats, premultiplied/64-bit conversion, alpha behavior, mean/luminance semantics, dimension rejection, stale-result clearing, missing/invalid inputs, input immutability, deterministic perceptual identity, invalid perceptual settings, image size limits and GUI loading/layout.
- 30 independent CLI checks passed. These use PNG fixtures generated by Python's standard library, exercise stdout and exit codes, thresholds, invalid arguments/settings, output refusal/failure, Unicode input paths and immutable inputs.
- The portable folder's SHA256 manifest was verified, then the folder was copied to a path with spaces. Qt/plugin environment variables were removed and PATH was restricted to Windows System32. The full QtTest and CLI suites passed again.
- A running relocated GUI was inspected: Qt5Core, Qt5Gui, Qt5Widgets, Qwt, the Windows Qt platform plugin and loaded VC runtime modules all resolved to files in the portable package (file identity checked).
- The full native tests and 30 CLI checks also passed from a Unicode application path. Toolhelp's reported module path can be lossy on such paths, so runtime module identity was checked separately on the space-containing ASCII path.
- The native GUI loaded a known image pair and rendered statistics and a difference mask. A screenshot was inspected. Default statistics docking and panel widths were corrected.
- The Qtbase source archive SHA256 matched the checksum published alongside it upstream.

## Rebuild identity

Two clean application build directories produced identical bytes for both application executables:

| File | SHA256 |
|---|---|
| diffimg.exe | 13ec9861698ac54e025cab4d4df85f6fca851aaf1b46b2b77952408a6264c601 |
| diffimg-cli.exe | a954f71549bf92a04ad1f1b74887b174569f9d22ee00b9d60ec2a6cc7fb3d613 |

Qwt's DLL was functionally rebuilt and tested in both directories, but **is not byte-identical across different build paths**. The observed DLL differences include MSVC-generated names for classes in anonymous namespaces in `.rdata`/`.data` and derived PE reproducibility information; the `.text` section was identical. This dependency limitation is retained rather than depending on undocumented compiler switches. The portable package pins the SHA256 of the actual Qwt DLL it contains. No claim of whole-package, cross-machine or cross-toolchain byte identity is made.

## Remaining limits

No clean VM or separate physical machine was available. Restricted-PATH relocation tests are evidence of app-local deployment, not a replacement for broader Windows version testing. x86, ARM64, other OSes, elevated contexts, full codec fuzzing, adversarial image corpora, HDR/color management and every perceptual setting combination remain unvalidated.

Qt 5.15.2 is an old dependency baseline. Image header/pixel bounds and the tested parser failures do not establish codec security. The source retains legacy warnings (including harmless null-thumbnail warnings during GUI initialization and compiler deprecation warnings from old Qt headers). No claim that the entire codebase is warning-free or fully reviewed is made.

Behavior changes are intentional: exact dimensions required; white-matte alpha normalization; corrected mean/luminance calculations; initialized perceptual output on identity; visible masks for one-unit blue differences; strict default batch comparison; explicit error exit code 2; no batch overwrite; settings beside the executable. Review README-WINDOWS.md before comparing results with older versions.
